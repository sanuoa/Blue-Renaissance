User Profile Page

Technical Description

The User Profile page (profile.html) uses the shared Blue Renaissance template, containing the standard <header> with the navigation bar, a <main> element that holds the entire profile-building interface, and the shared <footer>. Inside <main>, a <div class="profile-wrapper"> provides the centred, max-width layout. The page is divided into semantically meaningful sections: an introductory <div class="intro-box">, a progress indicator area, step-trigger buttons using <button> elements (which are keyboard-accessible by default), a status message <div>, and a profile output area built from nested <div> blocks, each corresponding to a step.

All three step blocks inside the profile output are hidden with display:none initially and revealed progressively using JavaScript DOM manipulation — specifically, adding a .visible class that switches them to display:block. This approach avoids page reloads and keeps everything within a single, clean HTML document. Embedded CSS handles all page-specific styles within a <style> block in the document head. Flexbox is used extensively: the step button row uses display:flex; flex-wrap:wrap; gap:12px to lay buttons out responsively. The progress bar is achieved through a fixed-height outer container with overflow:hidden; border-radius:20px and an inner <div> whose width property is transitioned smoothly using CSS transition: width 0.5s ease.

The User Profile page collects data using JavaScript's prompt() function. Collection is structured into three logical steps of three prompts each (nine prompts total), covering personal details, ocean interests, and conservation commitments. A profileData object stores all answers, and a stepStatus object tracks whether each step is 'pending', 'completed', or 'skipped'. Users may skip any individual prompt by pressing Cancel, or skip an entire step if they cancel all three prompts. A renderOutput() function uses DOM selection to update paragraph content dynamically, and updateRevisitButtons() generates revisit buttons for any skipped steps so users can return and complete them later.

Accessibility

The User Profile step buttons are standard <button> elements, which are natively keyboard-focusable. The mobile navigation toggle button uses aria-expanded to communicate open/closed state. White text on the deep teal (#053A40) background exceeds the WCAG AA 4.5:1 contrast ratio for normal text. The page has a lang attribute set to English so screen readers know what language the content is in.

Sitemap Page

Technical Description

The Sitemap page (sitemap.html) uses the shared template. The <main> section contains a heading, a brief description paragraph, and the SVG sitemap wrapped inside a responsive <div class="svg-container"> that provides overflow scrolling on small screens. The SVG element itself uses a viewBox="0 0 900 560" attribute with width="100%" so it scales proportionally at any screen width without losing aspect ratio or content.

Each node in the SVG is built as an <a> element wrapping a <g> group containing a <title> for screen-reader accessibility, a shape (<rect> or <ellipse>), and a <text> label. The <a> elements include tabindex="0" and role="link" with aria-label attributes to ensure keyboard and screen-reader users can navigate the sitemap. Connector lines between nodes are drawn using <line> elements with a custom SVG <marker> defining arrowheads. Node hover interactivity is implemented using embedded CSS which transitions the fill colour and stroke width on hover. A :focus style using outline: 3px solid #ffc107 provides a visible keyboard focus indicator.

SVG was chosen because it is resolution-independent, natively supports hyperlinking within elements, is searchable and accessible to screen readers, and validates as part of the HTML document. Using viewBox ensures the diagram scales cleanly across devices. The colour hierarchy — darkest for top-level pages, progressively lighter for deeper levels — gives users an immediate intuitive understanding of the site structure. Student 4's own pages are highlighted with a distinctive lighter border and a star symbol (★) to clearly identify individual contributions within the group structure.

Accessibility

The Sitemap SVG nodes use tabindex="0" on their <a> wrappers with aria-label descriptions, and a visible :focus outline ensures keyboard users can see which node is active. The SVG container has a role="img" and aria-label describing the diagram. Each SVG link includes a <title> element for screen reader identification. A colour legend below the SVG uses a flex row of small coloured swatches to explain the hierarchy visually.

Content Page — Sustainable Fishing

Technical Description

The Content page (content_ST4.html) uses the shared template and is structured around semantic HTML5 elements. One <h1> provides the page title (Sustainable Fishing), and six <section> elements each carry an <h2> heading and an id attribute for internal anchor linking. Sections cover: Introduction, Why It Matters, Unsustainable Methods, Sustainable Solutions, By the Numbers (data table), and Take Action. An internal navigation <nav> block at the top uses anchor links to allow users to jump directly to any section. A data <table> in the statistics section uses <thead>, <tbody>, <th>, and <td> elements correctly. A fixed "Go to Top" <a> button links back to the id="top" placed on the <body> element.

The content page uses embedded CSS within a <style> block containing more than five distinct rules. The internal navigation bar uses display:flex; flex-wrap:wrap with pill-shaped link styling (border-radius:20px). Section headings use a left-border accent (border-left: 4px solid #7ecfda) for visual hierarchy. Images use object-fit:cover with a fixed height:300px to maintain consistent visual proportions. A custom "fact box" component uses a linear-gradient background and a coloured border to visually separate key statistics from body text. The Go to Top button uses position:fixed; bottom:30px; right:30px — implemented entirely in CSS with no JavaScript.

Accessibility

All page content is original and written specifically for this coursework. All four images include descriptive alt attributes. The heading hierarchy is strictly sequential (h1 → h2 only). The internal navigation is wrapped in a <nav> element with an aria-label="Page sections" attribute so assistive technologies can identify it separately from the site navigation bar. The data table uses <th> elements with implicit column scope for screen-reader compatibility.

Challenges and Lessons Learned

The most significant challenge was designing the User Profile page's JavaScript step system to handle all edge cases: users who skip every prompt in a step, users who complete some prompts and skip others within the same step, and users who revisit and partially fill in previously skipped steps. The initial approach used a simple counter, but this led to double-counting when revisiting steps that had already been partially completed. The solution was to track the answered count globally and prevent re-incrementing by checking whether a value already existed in the profileData object before adding to the counter.

For the SVG sitemap, calculating x/y coordinates for node placement required iterative manual adjustment since SVG positions are absolute. I drew a rough layout on paper first, then converted measurements into SVG coordinates, which made the process significantly faster. Getting arrowhead markers to render at the correct scale and position required careful tuning of the refX, refY, and markerWidth attributes, which are not immediately intuitive from documentation alone. Working within a shared template also taught me to be disciplined about separating page-specific CSS from global styles.

  • All code and written content was produced personally and has not been plagiarised from other students or from online templates.
  • All pages have the correct charset and viewport settings in the head.
  • The website presents a positive, constructive message focused on environmental awareness and individual action.
