Splash Screen

Technical Description

The splash screen is a single page where all the CSS and JavaScript are written directly inside the HTML file itself rather than in separate files. It automatically redirects to the home page after 4 seconds using a meta refresh tag in the head. The whole page is centered using flexbox, and the background is a gradient that goes from a light green at the top to a dark ocean blue at the bottom to give it an underwater feel.

I used a custom font called Aestera for the main heading, which I loaded using a font-face rule pointing to the font file in the resources folder. Instead of a regular loading spinner I made a fish swimming across a bar. There is a thin orange bar and a fish image that both move from left to right together over 4 seconds using JavaScript's setInterval, which updates the position every 30 milliseconds. The skip button lets the user go straight to the home page without waiting.

Accessibility

The fish image has an alt attribute so screen readers can understand what it is. The skip button is a proper button element so it works with keyboard navigation. The page has a lang attribute set to English so screen readers know what language the content is in. The text colours are light enough against the dark background to be readable.

Action Impact Simulator (AIS)

Technical Description

The AIS page uses the shared header and footer from the site template. The action cards are arranged in a grid layout that automatically adjusts depending on the screen size, so they reflow into fewer columns on smaller screens without needing to write extra CSS for it.

Each card has a data attribute that stores how many impact points it is worth. When a card is clicked, JavaScript reads that value and adds it to the total score. I used a Set to keep track of which cards are selected so the same card cannot be counted twice. The score is split into three levels — low, medium and high — and depending on which level the user reaches, a different class gets added to the body element, which changes the background colour of the whole page through CSS. Cards can also be selected using the keyboard by pressing Enter or Space.

Accessibility

Each card has a tabindex so it can be reached by keyboard, and an aria-pressed attribute that updates when the card is selected or deselected so screen readers know its state. All card images have alt text. The reset button is a proper button element. The background colours used for each impact level are light enough that the card text stays readable on top of them.

Content Page

Technical Description

During the development of the content page I came across a few technical issues when running the W3C validator. The first was a typo in the CSS where it was written 0.9srem instead of 0.9rem for a gap value in the side navigation this was a simple spelling mistake that I fixed straight away.Two other issues came up a space in the logo image file path and a heading level skip in the footer where an h4 followed an h2 — but after reviewing them I decided to leave these as they were for now since they did not affect how the page looked or functioned.

Accessibility

For the content page I tried to make it as accessible as I could. All four images have alt text that describes what is shown in them. The page has a proper heading structure going from h1 down through h2 and h3 so that someone using a screen reader can follow the content easily. The sticky sidebar navigation uses anchor links so users can jump to any section without scrolling through the whole page. The go to top button is always visible in the bottom right corner for easier navigation. The page also has a lang attribute set to English and a viewport meta tag so it works correctly on all screen sizes.

Challenges and Lessons Learned

The biggest challenge I faced was trying to get a 3D jellyfish model to spin on the splash screen. I found a free jellyfish FBX model and tried to load it using Three.js, a JavaScript library for 3D graphics in the browser. I set up the scene, the camera, the lights and the loader but no matter what I tried the model just refused to show up. Even after spending a lot of time troubleshooting it and making sure everything was correctly set up, it still did not work. Since we are still in the early stages of learning JavaScript and have not covered anything like 3D rendering, I think it was just too complex for where we are right now. In the end I replaced it with a simple fish PNG that swims across a loading bar using basic JavaScript, which actually ended up looking better and more in line with the rest of the site's style. This taught me that sometimes a simpler solution works better, and that it is important to know when to change approach rather than keep pushing something that is not working.

Another issue I ran into was with the AIS page background colour. I had set up the three impact levels to change the background but when I tested it, only the feedback box was changing colour and not the whole page. After looking through the JavaScript I realised I was only adding the class to the feedback box element and not to the body. Once I moved it to document.body it worked properly.
