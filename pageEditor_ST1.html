Home Page

Technical Description

The home page is the main landing page for the site. It has a hero section, a "Why SDG 14 Matters" section with three cards, and an explore section with four gallery tiles. All CSS for the page is written in a style block inside the HTML file. Two Google Fonts are loaded — Playfair Display for headings and DM Sans for body text.

The hero section uses a two-column grid. The left side has a heading, a short paragraph, and two call-to-action buttons. The right side shows four stat boxes in a two-column grid. The stat numbers count up from zero when they scroll into view, using requestAnimationFrame with an ease-out cubic formula to make the counting feel smooth. The hero heading and text fade in from below using a CSS slideUp keyframe animation. Three decorative bubble shapes float up and down behind the hero content using a CSS floatUp animation.

The cards and gallery tiles start invisible and slide into view when the user scrolls down, using the IntersectionObserver API. Each item has a slightly different delay so they appear one after another rather than all at once. JavaScript event listeners handle hover highlighting on the gallery tiles and allow keyboard navigation with Enter or Space. The sticky header gets a stronger drop shadow added by JavaScript when the user scrolls more than 10 pixels down.

Accessibility

The hero section uses aria-labelledby pointing to the h1 heading so screen readers can identify the section. The "Why SDG 14 Matters" section does the same with its heading. The nav logo has an aria-label and the mobile toggle button has aria-label="Toggle navigation" and an aria-expanded attribute that updates when the menu opens or closes. The current page link has aria-current="page". The gallery tiles are elements with aria-label attributes describing where each one goes. The three decorative bubble divs are purely visual and do not carry any text, so they do not affect screen readers. The page has a lang="en" attribute and a viewport meta tag so it scales correctly on all devices.

Gallery Page

Technical Description

The gallery page has a hero banner at the top built with a CSS linear gradient that goes from dark teal to a lighter blue. Below that, the images are arranged in sections using a three-column CSS Grid. On smaller screens the grid automatically switches to two columns, and then one column on very small screens, using media queries.

Each card has three parts: a thumbnail image at the top, a title bar in the middle, and a hidden description panel at the bottom. When the user hovers over a card, the image zooms in slightly and dims, a "Click to explore" chip slides up from the bottom of the image, and the description panel smoothly expands using a max-height animation. The align-items: start rule on the grid stops the whole row from growing tall when one card's description opens.

When a card is clicked, JavaScript reads its data-* attributes to get the title, description, image, and badge text, and then fills in and opens a modal popup. The modal has a customisation panel with buttons to switch between four colour schemes (Ocean, Seafoam, Sandy, Deep Sea) and four font styles (Default, Serif, Monospace, Rounded). These are applied by changing inline styles on the modal box. The modal closes when the user clicks the X button, clicks outside the box, or presses Escape.

Accessibility

Each gallery card has a tabindex="0" so it can be reached with the keyboard, and JavaScript listens for Enter and Space key presses to open the modal, the same as a click. The modal element has role="dialog", aria-modal="true", and aria-labelledby pointing to the modal title, so screen readers announce it correctly when it opens. When the modal opens, focus is moved to the close button straight away. The close button has an aria-label so its purpose is clear. The small arrow icon inside each card label has aria-hidden="true" so screen readers skip it. Cards also show a visible focus outline when tabbed to. The page has a lang="en" attribute and a viewport meta tag.

Content Page

Technical Description

The content page uses the shared site header, footer, and stylesheet. The page layout is built with CSS Grid, splitting the screen into two columns — a narrow sticky sidebar on the left and the main article on the right. The sidebar stays in place as the user scrolls, always showing the section links. The gap value in the sidebar uses a CSS custom property, and the styles are written inside a style block directly in the HTML file rather than in a separate CSS file.

The article is divided into five sections: an introduction, coral reefs, key threats, student actions, success stories, and a get involved section. Three images are placed inside

Challenges and Lessons Learned

The biggest challenge I faced was building the gallery page pop-up modal using JavaScript. I had not worked much with JavaScript before, so figuring out how to open the modal, fill it with the right image and text from each card, and then close it properly took a lot of trial and error. Getting the Escape key and outside-click close to work at the same time as the close button was tricky, and I had to look up how event listeners work to get it right. The JavaScript on the home page was also difficult. Adding the scroll-reveal animation using IntersectionObserver, making the stat numbers count up smoothly, and handling the hamburger menu toggle all at once felt like a lot to manage together. It took me several attempts to get the counter animation to feel natural and to make sure the menu opened and closed correctly on mobile.

Working through these challenges taught me quite a bit about JavaScript that I did not know before. I learned how data-* attributes can be used to store information on HTML elements and then read them with JavaScript, which is how the modal gets its content from each card. I also learned how IntersectionObserver works and how useful it is for triggering things when they scroll into view, rather than constantly checking the scroll position. On the CSS side, I got more comfortable with things like max-height transitions for smooth expand and collapse effects, clamp() for font sizes that scale with the screen width, and align-items: start on a grid to stop rows from stretching unexpectedly. Overall, building these two pages gave me a much better understanding of how JavaScript and CSS work together to create interactive and responsive pages.
